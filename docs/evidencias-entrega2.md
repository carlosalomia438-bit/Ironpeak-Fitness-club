# Evidencias – Evaluación 3, Entrega 2

Este documento indica las evidencias que se deben mostrar para respaldar la Entrega 2. Las evidencias deben corresponder al estado real del proyecto.

## 1. Repositorio

Mostrar el repositorio de GitHub y su estructura principal:

- `README.md`
- carpeta `docs/`
- carpeta `src/`
- carpeta `tests/`
- carpeta `.github/workflows/`

**Evidencia sugerida:** captura de la página principal del repositorio.

## 2. Historial de Git

Mostrar que el proyecto tiene evolución y no fue entregado mediante un único commit.

**Evidencia sugerida:** captura de la pestaña de historial de commits donde se vean los diferentes cambios de documentación, estructura, código base y CI.

## 3. Documentación

Verificar que estén disponibles:

- `docs/requisitos.md`
- `docs/arquitectura.md`
- `docs/modelo-datos.md`
- `docs/documentacion-funcional.md`
- `docs/instalacion-configuracion.md`
- `docs/control-cambios.md`

**Evidencia sugerida:** captura de la carpeta `docs/`.

## 4. Integración continua

Mostrar el archivo:

`.github/workflows/ci.yml`

La evidencia final debe mostrar una ejecución del workflow **CI** terminada correctamente. El pipeline debe demostrar que el proyecto puede restaurarse y compilarse automáticamente.

**Importante:** no se debe presentar una ejecución como exitosa hasta que GitHub Actions muestre realmente el resultado correcto.

## 5. Ejecución local

Cuando se abra la solución en Visual Studio, tomar una captura que permita comprobar que la solución base abre y puede ejecutarse.

La funcionalidad completa del gimnasio todavía no está implementada, por lo que esta evidencia corresponde únicamente a la base técnica disponible en esta entrega.

## 6. Funcionalidades

En esta etapa no se deben inventar capturas de pagos, horarios, nutrición o rutinas. Esas capturas se agregarán cuando las funcionalidades estén implementadas.

## 7. Qué mostrar al profesor

Orden recomendado:

1. Repositorio de GitHub.
2. README y estructura de carpetas.
3. Historial de commits.
4. Documentación técnica y funcional.
5. Archivo de CI.
6. Ejecución exitosa de GitHub Actions.
7. Ejecución local de la solución base.
8. Explicación breve de qué está implementado y qué queda para la siguiente etapa.
